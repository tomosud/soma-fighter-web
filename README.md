# SOMA Fighter Web

NVIDIA [MotionBricks](https://github.com/NVlabs/motionbricks)（SOMA モデル）を**ブラウザの WebGPU で動かし**、その場で生成した動きだけで戦う 1 対 1 の格闘ゲーム。サーバーは要らず、GitHub Pages の静的ファイルだけで動く。

用意したアニメーションは再生しない。構え・打撃 6 種・のけぞり 5 種・ダウン 2 種・勝ちポーズの**キーポーズだけ**（Mixamo のモーションを SOMA に移したものから、当たる瞬間などの 4 フレームずつ。`assets/keyposes.json`）を相手の今の位置に合わせて置き（打撃は IK で手足の先を相手の頭・あご・胴へ届かせ）、そこまでの動きを MotionBricks が毎回生成する。2 人分の生成は 1 回の推論にまとめる。

デスクトップ版 SOMA Fighter（TensorRT サーバー + ブラウザ描画）の考え方を参考にした、最小限のブラウザ版。

## 遊ぶ

GitHub Pages の URL を開き、「モデルを読み込んで始める」を押す。初回は NVIDIA の GitHub からモデル（Mixed FP16 で 380 MB）をダウンロードしてブラウザ（IndexedDB）に保存する（2 回目からは保存したものを使う）。

| 操作 | キー |
|---|---|
| 前後に動く | A / D（矢印も可） |
| 横に動く（奥 / 手前） | W / S |
| ジャブ | J（左クリック） |
| ストレート | L（中クリック） |
| フック | U |
| アッパー | I |
| ミドルキック | K（右クリック） |
| ハイキック | O |

2 本先取。届かない距離で打つと空振りになる。打たれると打撃は止まる。

### 必要なもの

- WebGPU が使えるデスクトップの Chrome / Edge（WebGPU が無いと WASM（CPU）で動くが、かなり遅い）
- 数 GB の空きメモリ

### 測った値

| 環境 | 1 回の生成（2 人分） |
|---|---|
| WebGPU、NVIDIA Turing（Claude デスクトップの Chromium 152） | 約 120〜170 ms |
| Node の onnxruntime（CPU） | 約 80 ms |

バッチの大きさを 2 に固定して ONNX Runtime に形の計算を畳ませると、可変のときより約 3 割速い（WebGPU で約 180〜230 ms → 120〜170 ms）。生成にかかる時間のぶん先の姿勢から生成を始め、届いたら続きとしてつなぐ（`src/motion.js`）。間に合わなければ 0.18 秒で混ぜてつなぐ。

## SOMA Pull（`lab.html`）

生きている人を引っ張っているように動かすツール。黄色の球（手・腰・頭・足）をつかんで引っ張ると、体がついてくる。水色の球で見る方向を変えられる。床は果てしなく続き、カメラがついてくる。

1. **ひもと、引く距離で変わる先読み**：つかんだ点はひもが張ってから体を引き、張った長さで行きたい速さが決まる（上限 1〜3 m/s、加速も制限、腰は上がらない）。少し引いたときは約 0.5 秒先、遠くまで引いたときは最大 1.4 秒先まで計画し、作り直す間隔も 0.18〜0.3 秒で変わる。
2. **動いている途中の目標**：予測した経路の上に 1/30 秒おきの目標を 4 枚置くので、MotionBricks が自分で足を踏み替えて歩く・走る。歩きの目標は、モデル自身の出力から育てたポーズ集（速さ × 向き × 着いている足）から選ぶ。
3. **立っているときは体をモデルに任せる**：止まる・立つときの目標は腰の位置と向きだけを決め、体の姿勢は拘束しない（モデル本来の自然な立ち方になる）。数秒おきに数 cm 重心を移す。
4. **画面は SOMA の出力そのもの**：表示には物理も IK も重ねない。間の動きはすべて SOMA が作る。こちらが作るのは目標の姿勢だけで、それも SOMA が直前に出したフレームから作る。
5. **目標の作り方**：SOMA の直前のフレームに、(1) 引かれた反応の姿勢を少し混ぜ、(2) 見えない物理が予測した体の反応（腰の位置と体幹・脚の傾き）を加え、(3) つかまれた手足だけを IK で伸ばし、(4) 視線を向ける。片手を引いたときは、反対の腕をつかんだ瞬間の形に保つ（SOMA は片手を伸ばすと両手を出しがちなため）。手は「目標に届く頃に指がある位置」を狙う。指が動いたとき、または物理が予測する傾きがはっきり変わったときだけ作り直すので、指を止めれば動きは最後まで再生されて目標に届く。その場で手を伸ばす動きは 1.3 倍で再生する。
6. **見えない物理（`src/ragdoll.js`）**：重さのある約 30 個の粒子を、関節ごとの「筋肉」で SOMA の動きに追わせ、つかんだ部位をばねで引く（XPBD、床と、着いている足の摩擦）。引っ張っている間は薄い人形で見える。見えない体の腰が SOMA の腰から押し出され、その差の向かう先（差 + 差の速さ × 0.31 秒）が 10cm を超えたら、その向きへ踏み出す目標を出す（立っているときとゆっくりのときだけ）。
7. **SOMA の出力から育つポーズ集**：歩きの 4 フレーム（速さ × 向き × 着いている足）に加え、引かれている間に SOMA が作った中間の姿勢を「どこを・体から見てどの向きへ」引かれたかで集め、次に同じように引かれたときの目標に混ぜる。
8. 視線のノブ（水色＝正面、ピンク＝体に対して固定）は目標の頭・首・胸に入る。
9. **歩きの姿勢**：歩きの目標は上半身を自然な前傾（3° ＋ 速さ 1 m/s あたり 2°）まで起こしてから渡し、前傾 12° を超える窓はポーズ集に入れない（最初の直立の目標から前かがみの歩きが育ち、猫背になっていた）。引っ張っている間の視線は、胸は左右に回すだけで上下は首と頭で見る（腰や足をつかんだときは前を見る）。胸ごと下を向いて前かがみになっていた。前傾は腰で引いて 14.8° → 2.8°、手で引いて 18.9° → 6.7°。
    - **向きの変え方**：引く向きが変わったら、速さを保ったまま進む向きだけを回す（毎秒 4.5 rad まで）。90° 向きを変えると 0.27 秒で移動の向きが変わる。足が着くたびに作り直すのは実際に歩いているときだけなので、歩き出しで止まらない。
10. **歩きの足運び**：目標の時点でどちらの足が着いているかを、SOMA が直前に実際に踏んだ歩調から予測する。安定して歩いている間は、足が着いた瞬間ごとに（または向きが 25° 以上変わったときに）作り直すので、一歩の途中で足の形が入れ替わらない。まっすぐ手で引くと、一歩の間隔のばらつきが ±12 → ±6 フレームになった（曲がりくねって引くと、まだ 10 秒に数回つまずく）。
11. **キック**：足を素早く（1.5 m/s 以上で）上げて膝より上（0.3m 以上）へ引くと、指が止まるか 0.25 秒たった時点で、その先へ一発蹴る。軸足は今の位置に置いたまま体を回し（滑らない）、速く引くほど速く再生する（1.4〜2.6 倍）。蹴った後の戻りは SOMA に任せ、目標では脚と骨盤だけを蹴る前の形へ戻す（上半身は SOMA のまま）。目標は Mixamo 由来のキックのキーポーズ（高さ 1.05m 未満はミドル、以上はハイ。左足は左右反転）で、蹴る足が指の方を向くように体を回し、遠ければ踏み込み、足先だけ IK で指へ合わせる。抱え込みから伸ばすまでの動きは SOMA が作る。測った値：右ミドル（0.9m）・左ハイ（1.3m）・右ハイ（1.25m）とも 0.5 秒以内に足先が指へ届いて保ち、離すと 0.7〜1.0 秒で両足立ちに戻る。

12. **足を保つ**：足をふつうの速さで上げると、蹴らずに指についてくる（足が床を離れるたびに速さで決め直す）。目標は、つかんだときの姿勢を今の位置へ運んだものに全身の連鎖（重心を軸足の上へ、体幹は反対へ、両腕を開く）をかけ、上半身は SOMA の直前の姿勢と 3 割混ぜる（こうすると、作り直すたびに傾きが積み重ならない）。軸足は今の位置のまま、上げた足は腰の高さまで。指を止めている間も同じ目標で生成を続けるので、片足で立ったまま固まらない。この間は、見えない物理によるよろけと押し戻しを止める。離すと、足をその真下（軸足から 0.2〜0.6m）に平らに置き、腰を元の高さへ戻す。
13. **歩くだけにしない**：
    - **全身の連鎖を目標に入れる**：立って引かれているときの目標に、つかんだ部位から全身へ伝わる連鎖を半分ほど混ぜる。低い所へ手を伸ばすと膝を曲げ、遠くへ伸ばすと腰が寄り、反対の腕でバランスを取る。腰を引くと上体が起き、頭を引くと腰が逆へ逃げる。
    - **つかむたびの癖**：つかむたびに「どれだけ体が持っていかれるか・どれだけしゃがむか・腕をどれだけ開くか」を乱数で決め、そのつかみの間は固定する（作り直すたびにちらつかない）。
    - **踏み込み**：ひもが張ってから 15cm までは歩かず、引かれた方にある足を一歩（0.22〜0.5m）出して腰を半分寄せ、前の膝を曲げる（1 秒に 1 回まで）。それより引くと歩く。
14. **ポーズがポーズを生む（作ったポーズ）**：指を約 1 秒止めて SOMA の体が落ち着いたら、その姿勢を「何を・体から見てどの向きへ・どの高さへ」引いたかで残す（片足を保って離したときも）。次に同じように引くと、残したポーズの 1 つから体幹（とつかんだ腕）を、同じ部位の別のポーズから反対の腕を取って目標に混ぜる（3 割）。そこから SOMA が作った姿勢がまた残るので、組み合わせから新しい姿勢が育つ。前傾 35° 以下・片足は床・腰の高さが範囲内のものだけ残し、ほぼ同じ姿勢は増やさず、いっぱいになったら一番近いものと入れ替える（同じ姿勢ばかりにならない）。
15. **アナログな歩き**：引く強さを、そのまま行きたい速さにする（少し引けばゆっくり、強く引くほど上限に近づく、なめらかに頭打ち）。上限は後ろ向きで 55%、横向きで 80%。同じドラッグから歩き方も読む。腰を低く引く・手を低く引くとかがんで歩き（腰が最大 24cm 下がり、遅くなる）、頭を下へ引くと背を丸め、上へ引くと胸を張る。歩きの目標を選んだ後にこの形をかけ、足の位置は IK で保つので、足運びは SOMA のまま。ゆっくり横へ引くと、向きを変えずに横へ踏み出す。
16. **ジャンプ**：腰をつかんで素早く上へはじく（1.2 m/s 以上）と小さく跳ぶ（腰の上がり 12〜30cm、はじいた向きへ最大 45cm）。目標は空中の頂点の 4 フレーム（重力どおりの弧）と着地（膝で受ける）の 2 つだけで、しゃがむ溜め・踏み切り・着地の吸収は SOMA が作る。測った値：はじいてから約 0.6 秒で跳び、両足が 20〜25cm 浮く。
17. **嫌がる・困る・転ぶ**：操作は増やさず、引き方から気持ちが出る。
    - **嫌がる**：ついて来られる速さより強く引き続けたり、離してすぐつかみ直したりすると、だんだん嫌がる。ひもが緩く・弱くなって足を引きずるように遅くなり（測った値：1.84 → 0.98 m/s）、体を引かれる方と反対へ反らし、顔をそむける。休ませると戻る。
    - **困る**：短い間にあっちこっちへ振る（2 秒ほどで 4 回向きが反転する）と立ち止まり、片手を頭へやり、首をかしげて左右を見回す。
    - **転ぶ**：嫌がっているのにそのまま 4 秒ほど引きずる、片足で立たせた足を遠くまで引く、頭を低く（0.75m 未満へ）引く、のどれかで、引かれた方へ倒れ（後ろへ引かれたら仰向け、ほかはうつ伏せのキーポーズ）、少し寝てから自分で起き上がる。起き上がりは SOMA が作る。
18. **歩きのつまずきを減らした**：見えない物理の「倒れそうなら踏み出す」判定が、ふつうに歩くだけで出ていた（まっすぐ 16 秒歩いて 19 回。片足立ちの瞬間はいつも重心が足の外にあるため）。そのたびに速さを足して計画を作り直し、足運びを乱していた。判定を「見えない体が SOMA の動きからどれだけ押し出されたか」に変え、歩いている間（0.45 m/s 以上）は使わない。0 回になり、同じ足が続けて着く回数も 0 回になった。
    - 試してやめたこと：歩きの目標を脚の形から測る位相で選び、生成の長さを 1 つに固定して、目標が遊脚の中ほどに来るようにした。測ると、つまずきの指標はかえって少し悪くなったので戻した（SOMA に長さを選ばせる方が、本人の歩調に合う）。

片手を引くと、引いた腕は 71〜79° 動き、反対の腕は 9〜13°（ふつうの揺れ）。上下に 0.5 m/s で動かす指への遅れは 0.36m → 0.27m。

測った値（1/60 秒刻み、揺れ＝フレームごとの加速度の大きさの平均）：何もしないと揺れ 0.010、腰 0.99〜1.00m。手を肩から 0.85m 先へ引くと、手は 0.83m → 0.2m まで寄り、体幹が 23° 傾き、腰が 0.94m 寄る。手を急に横へ引くとよろけて踏み出し 1.94m 動く。手・腰で引いて歩くと 1.36 / 1.35 m/s、揺れ 0.089 / 0.10（物理を重ねて表示していた版は 0.14 / 0.21）、両足が 18cm より上がる時間 0% / 0.3%。

## 仕組み

```
src/
  soma.js          骨格（30 関節）、順運動学、MotionBricks の入力エンコード・出力デコード・端点補正
  poses.js         キーポーズ：keyposes.json の読み込み、打撃を点へ届かせる 2 関節 IK（KeyBook）。手で作る版（PoseBook）も残す
  motion.js        Track（再生中の動きと、生成した動きのつなぎ方）と Scheduler（2 人分を 1 回にまとめる）
  infer.worker.js  ONNX Runtime Web（WebGPU、だめなら WASM）、モデルのダウンロードと IndexedDB への保存（Blob 1 つ）
  render.js        three.js：カプセルの人形、床、2 人を横から映すカメラ
  main.js          試合：入力、CPU、当たり判定、ラウンド
  lab.js           SOMA Pull：ひも、可変の先読み、SOMA の中間から作る目標、育つポーズ集（歩き・引かれた反応）、踏み出し、視線、果てしない床
  ragdoll.js       見えない物理：粒子・筋肉・床・摩擦（XPBD）と、粒子から関節の回転への戻し
assets/soma_rig.json   公式の骨格 USD から取り出したレスト姿勢
assets/keyposes.json   キーポーズ（SOMA Fighter の clips.npz のうち Mixamo 由来のクリップから）
tools/
  extract_rig.py   USD → soma_rig.json（uv run --with usd-core python tools/extract_rig.py <usd>）
  bake_keyposes.py clips.npz → keyposes.json（uv run --with numpy --with scipy python -I tools/bake_keyposes.py <clips.npz> <clips.json>）
  smoke.mjs        Node でモデルを動かす試験（エンコード → 推論 → デコードの誤差）
  serve.mjs        ローカル用の静的サーバー
```

- 入力は「直近 4 ポーズ（文脈）+ 目標ポーズ 1 枚」。最後の文脈が +X を向くように整列して、根の位置・向き・速度、関節の位置、6D 回転にする（公式 `kernels.py` と同じ）。
- 出力（24〜64 フレーム）の両端 3 フレームを除き、始まりを文脈の最後に、終わりを目標に合わせる（公式の端点補正と同じ）。だから打撃は IK で置いた点へ正確に届く。
- 打撃は短い生成（6 トークン = 18 フレーム）を 1.6〜2.1 倍速で再生する。当たったかは、手足の先と相手の頭（球）・胴（カプセル）の距離で判定し、ダメージは当たる瞬間の速さで変わる。

## ローカルで動かす

```bash
npm install
npm run serve
```

http://127.0.0.1:8080/ を開く。ダウンロード済みのモデルを `models/` に置けば `?model=models/mmm_v6_soma_fp16.onnx` で使える（`models/` は Git に入れない）。`?ep=wasm` で WASM、`?debug` で `window.game` から状態を読める。

Node で推論を試す：

```bash
npm run smoke -- models/mmm_v6_soma_fp16.onnx
```
